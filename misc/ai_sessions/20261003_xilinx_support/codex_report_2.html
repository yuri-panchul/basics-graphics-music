Vivado installation discovery: Codex vs Claude

Comparison 2 · 3 October 2026 · Current local file snapshots

Codex is stronger on sort compatibility and symlink discovery. Claude is stricter about version-directory names and separates discovery into smaller helpers. Both now search only versioned layouts automatically; neither gives priority to unversioned installations.

How an installation is chosen, in plain English

A parent is a location such as /opt. A vendor is Xilinx, AMD, or AMDDesignTools. Both implementations recognize:

<parent>/<vendor>/Vivado/<version>/bin
<parent>/<vendor>/<version>/Vivado/bin

Location priority comes before version priority. For example, if XILINX_HOME points to a parent containing 2025.2, neither script chooses 2026.1 from /opt instead.

Codex selection steps

  1. If the platform is not Linux, Cygwin, or MSYS, return without configuring Vivado.
  2. If XILINX_VIVADO is set and its bin directory exists, append that bin directory to PATH and stop. Warn and continue if the directory is missing.
  3. Otherwise, if the vivado command is already available through PATH, stop searching.
  4. Try XILINX_HOME first when it is set. Then try HOME, /opt, and /tools on Linux, or /c, /d, and /e on Cygwin/MSYS.
  5. Within each parent, check Xilinx, AMD, and AMDDesignTools. Look for vendor/Vivado/version/bin and vendor/version/Vivado/bin. A bin directory is enough to count as a candidate; the executable is not checked.
  6. Use the first parent with any candidates. Do not search later parents for a newer release. Directory names are not required to start with a number.
  7. Find a sort program that correctly puts 2026.2 before 2026.10. Try /usr/bin/sort, /bin/sort, then sort on PATH. If none passes, warn and use sort without options.
  8. Sort candidates by version, remove carriage returns, and select the last candidate. If sorting fails, report an error. Plain fallback sorting can choose an older version.
  9. Set XILINX_VIVADO to the selected directory and append its bin directory to PATH. Report multiple candidates when present. If all parents were empty, report an error.

Claude selection steps

  1. Use the same platform check, explicit XILINX_VIVADO override, and existing-PATH shortcut as Codex.
  2. Try the same parents in the same order: XILINX_HOME first, then the platform defaults.
  3. For each parent, call a helper that checks the centralized list Xilinx, AMD, AMDDesignTools. It uses find to list immediate version directories in both layouts.
  4. Keep only directory names starting with a digit and candidates with a bin directory. Symlinked version entries are not returned by find -type d.
  5. Once one parent supplies candidates, subsequent parent-helper calls do nothing. A newer installation in a later parent does not override this choice.
  6. Try sort -V from PATH on empty input. If the command succeeds, use it. Otherwise warn and use sort without options. It does not search explicit Unix sort locations.
  7. Sort version-plus-path lines, remove the version prefix with sed, and take the last path with tail. Windows carriage returns are not removed.
  8. Set XILINX_VIVADO and append its bin directory to PATH. Use xargs echo to format the candidate list and warn when more than one installation is found. If no candidates were found, report an error.

Advantages and disadvantages

Codex advantages

  • Stronger Unix sort discovery and a behavioral probe, reducing accidental use of Windows sort.exe.
  • Normalizes Windows line endings and explicitly reports sorting failures.
  • Recognizes symlinked version directories and uses fewer external commands.
  • Local variables reduce interference with the rest of the sourced setup scripts.

Codex disadvantages

  • A folder such as backup can outrank actual numbered releases if it contains bin; reproduced in testing.
  • Discovery and selection remain combined in one larger function.
  • The sort helper relies on caller-local variable names rather than explicit output parameters.
  • Fallback alphabetical sorting still cannot guarantee the newest numeric version.

Claude advantages

  • Rejects nonnumeric names such as backup, reducing accidental selection.
  • Separate helpers make candidate collection and parent searching easier to inspect independently.
  • Vendor names are centralized and reused in diagnostic messages.
  • Override diagnostics give concrete examples of both installation layouts.

Claude disadvantages

  • Can use Windows fallback sorting even when a compatible /usr/bin/sort exists.
  • Windows fallback can leave a carriage return in XILINX_VIVADO, creating an invalid path.
  • Skips symlinked version directories.
  • Global shared state and more subprocesses make the implementation more coupled and verbose.
  • xargs-based diagnostic formatting is fragile for quoted or backslash-containing paths; sorting lacks its own error message.

Observed test results

Tests used temporary installation trees, including paths with spaces, and extracted the current discovery functions. Bash ran with errexit, nounset, and pipefail, matching the setup caller. Windows sort was simulated as accepting no options and emitting CRLF; no native Windows execution was performed. The no-installation cases used MSYS parent selection to avoid the real Linux installation.

Shared limitations

  • Finding a bin directory does not prove that Vivado is executable, licensed, or compatible with the host.
  • Both append to PATH. An existing earlier vivado command can still run instead of the installation named by an explicit XILINX_VIVADO override.
  • Neither chooses the newest version across every parent, and equal-version ties have no explicit vendor preference.
  • Both use line-based candidate lists, so embedded newlines in directory names are unsupported.
  • Automatic unversioned discovery is gone, but an explicit XILINX_VIVADO path or existing PATH entry can still refer to an unversioned installation.

Suggested direction

Keep Codex’s sort probing, CRLF cleanup, explicit sorting errors, and symlink support. Add a version-name filter inspired by Claude and consider separating candidate collection into a helper if that improves readability. Choose and document an explicit equal-version tie policy if duplicate installations are common.
