How an installation is chosen — plain English

Both support these layouts, where the vendor is Xilinx, AMD, or AMDDesignTools:

<parent>/<vendor>/Vivado/<version>/bin
<parent>/<vendor>/<version>/Vivado/bin
  1. Check the platform. Continue only on Linux, Cygwin, or MSYS. Otherwise return without setting up Vivado.
  2. Honor an explicit installation. If XILINX_VIVADO points to a directory containing bin, append that bin directory to PATH and stop. If the directory is invalid, warn and continue.
  3. Check the existing command path. If vivado is already found through PATH, stop searching. This checks command availability, not whether Vivado actually starts successfully.
  4. Choose where to search. Try XILINX_HOME first if set. Then try HOME, /opt, /tools on Linux; or /c, /d, /e on Cygwin/MSYS.
  5. Collect installations in one parent. Check all three vendor directories and both layouts. Require a version folder beginning with a digit and a bin subdirectory. Symlinked version folders count. Unversioned installations are not automatically discovered.
  6. Stop at the first parent with candidates. A version in XILINX_HOME wins over a newer version in /opt. The scripts choose the newest version within one parent, not across the entire machine.
  7. Find a version-aware sort. Both try /usr/bin/sort, /bin/sort, then sort on PATH and test 2026.2 against 2026.10. Codex safely skips a failing probe. Claude can exit immediately on a failing probe under the normal set -e execution mode.
  8. Sort and pick the last candidate. With Unix sort, 2026.10 beats 2026.2. Both intend to warn and use plain sort if version sorting is unavailable; Claude’s unguarded probe can prevent reaching that fallback. Plain sorting can select an older version.
  9. Publish the choice. Remove carriage returns, set XILINX_VIVADO, append bin to PATH, and report multiple candidates. Codex formats paths in Bash. Claude passes them through cut and xargs, which can fail on quotes.
  10. If nothing is found, report an error. Name the searched parents and explain how XILINX_HOME or XILINX_VIVADO can specify a location.

Advantages and disadvantages

Codex advantages

  • Safe sort probing under strict Bash error handling.
  • Explicit version/path sorting and reliable fallback behavior.
  • Handles quoted paths without xargs; preserves repeated spaces in candidate reporting.
  • Compact collection helper with explicit inputs, local vendor array, and fewer helper dependencies.
  • Explicit platform branches match the requested future-maintenance style.

Codex disadvantages

  • Silently ignores nonnumeric version folders, which can confuse users with renamed installations.
  • Candidate collection uses command substitution; the sort helper still relies on caller-local output variables.
  • Diagnostics are less detailed about override examples than Claude’s.
  • Fallback plain sorting cannot guarantee the newest version.

Claude advantages

  • Has caught up on numeric filtering, symlinks, Unix sort discovery, and CRLF cleanup.
  • Warns about some installation-shaped directories rejected by the numeric filter.
  • Provides concrete override examples and reuses list-building logic.
  • Most discovery state is now local to setup rather than globally leaked.

Claude disadvantages

  • A failing sort probe can abort the entire setup under set -e; reproduced.
  • xargs-based reporting can fail after selecting a valid installation; reproduced with an apostrophe in the parent path.
  • Ignored-directory warnings depend on whether earlier candidates have already been collected.
  • More helpers and implicit caller-local dependencies make state flow harder to trace.
  • Keeps a global vendor string and a generic Windows else branch.

Verified behavior

Eight scenarios ran against the current extracted discovery functions under set -Eeuo pipefail, using temporary installation trees with spaces in their parent paths. Logging helpers were stubbed; error exited with status 1. MSYS parent selection avoided real Linux installations. Failed Unix-sort probes and Windows CRLF output were simulated. No native Windows or end-to-end synthesis testing was performed.

Shared limitations

  • A bin directory is enough to qualify; the scripts do not verify the Vivado executable, license, or host compatibility.
  • Both append to PATH. An earlier vivado executable can still win even when XILINX_VIVADO names another installation.
  • Neither automatically supports versionless installations, though explicit XILINX_VIVADO and existing PATH can still refer to one.
  • The digit-prefix filter is not strict version validation: a name such as 2026-backup still qualifies.
  • Line-based records do not support embedded newlines. Tab-containing paths are problematic, particularly for Claude’s final-path extraction.
  • Both remove all carriage returns from sort output, including any literal carriage returns in unusual filenames.

Recommendations

  1. Keep Codex’s guarded sort probe. In Claude, put the probe assignment inside an if before testing its output.
  2. Keep Bash-based path formatting rather than xargs, so reporting cannot invalidate a successful discovery.
  3. Consider an ignored-directory warning, but collect rejected paths consistently and report them after scanning the parent rather than making the warning depend on vendor order.
  4. Retain explicit platform checks, the documented tie rule, and the existing shared behavior. More refactoring is optional, not a prerequisite for correctness.
