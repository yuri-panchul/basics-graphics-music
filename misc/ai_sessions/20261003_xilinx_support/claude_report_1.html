Vivado Discovery Review

Two independent rewrites of the same 160 lines of Bash that locate a Vivado installation. They pick the same directory in every case I could construct. The differences are robustness, hygiene and size.

file scripts/steps/00_setup_xilinx.source_bash branches xilinx_codex · xilinx_claude base origin/main @ eaa933c5 reviewed 2026-10-01

Verdict

Base on xilinx_codex, port the presentation from xilinx_claude.

The codex version's advantages are correctness under conditions this course actually meets — Windows shells, unusual directory names. The claude version's advantages are presentational: a single source of truth for the vendor list, cleaner diagnostics, and formatting that matches the file. Presentation is cheap to port; robustness is not.

What the script has to find

Both versions recognise the same three installation shapes under a vendor directory of Xilinx, AMD or AMDDesignTools, and give the versionless one priority within a parent directory:

<parent>/<vendor>/Vivado no version directory — highest priority <parent>/<vendor>/Vivado/<version> Vivado 2024.1 and older <parent>/<vendor>/<version>/Vivado Vivado 2024.2 and newer

Parent directories are tried in a fixed order — $XILINX_HOME, then $HOME, /opt, /tools on Linux, or /c, /d, /e on Cygwin and MSYS — and the first one holding an installation wins. $XILINX_VIVADO short-circuits the search entirely; a vivado already on PATH is left alone.

Selection is identical

I sourced both files from the same harness, under set -Eeuo pipefail with stub helpers, against identical fake installation trees. Every case resolves to the same directory.

Where they diverge

xilinx_codex

9e72950e · 5 commits

Advantages

  • Survives a shadowed sort. Probes /usr/bin/sort, /bin/sort, sort in order, so a Windows sort.exe ahead of GNU sort on PATH — the same hazard the repo already works around for find via $find_to_run — does not degrade it.
  • The probe is a functional test. It sorts 2026.10 against 2026.2 and checks the result, rather than only checking that -V is accepted.
  • Sorts the version field alone (-t $'\t' -k1,1V), so a path can never influence a version comparison.
  • Strips CR from sort output for Windows tools.
  • Proper local discipline — nothing leaks.
  • No find dependency — plain globs, one less external tool and immune to the find.exe problem.
  • Shorter and flatter. One loop over parents with an early return; no cross-parent accumulation, so no "first parent wins" guard is needed.
  • Accepts non-numeric version directories, e.g. Xilinx/Vivado/mybuild.

Disadvantages

  • Vendor list hardcoded three times — two loops plus the error message, so the search and its diagnostics can drift apart.
  • Multi-line warning through a single-line helper. It hands the tab-separated candidate list to warning, which does info warning: $* with unquoted $*; word splitting mangles the tabs and newlines.
  • Capitalised messages (Cannot find Vivado under:) break this file's own convention — every upstream message here starts lowercase. Other files in the repo do capitalise, so the point is narrow.
  • Dead code: return 1 after error, twice. error already exits.
  • Unquoted paths in the final error (${search_parents[*]}), ambiguous if a path contains a space.
  • Layout documentation is scattered inline rather than stated once.

xilinx_claude

fccb2e9e · 3 commits

Advantages

  • One source of truth for the vendor list. xilinx_vendor_dirs drives the loops and the error text alike, so they cannot disagree.
  • All three layouts documented in one header comment.
  • Single-line warning naming every candidate and which one was chosen.
  • Matches local conventions — lowercase messages, and the intel_fpga_try_install_dir helper idiom already used by the Quartus setup script.
  • Quoted paths in diagnostics; keeps the $find_to_run convention the repo established.
  • Names the junk it skips — DocNav, xic, .xinstall — via a [0-9]* version match.

Disadvantages

  • Degrades on a shadowed sort — selects the wrong version, with only a warning to show for it.
  • Weak sort probe — checks that the option is accepted, not that it works.
  • 11 leaked variables into the user's shell.
  • 142-column lines, 10 over 79 — the only one of the three revisions that breaks the file's formatting.
  • The [0-9]* filter silently discards legitimate non-numeric version directories, falling through to another parent without a word.
  • 40% more code for the same behaviour; retains an unreachable else error "unsupported OS" branch.

Evidence

Two cases separate them. Both were produced by shadowing a tool or creating a directory, then running each version through the same harness.

A sort that rejects -V is first on PATH 
$ PATH=$H/fakebin:/usr/bin:/bin  XILINX_HOME=$H/new   # holds 2026.9 and 2026.10

claude: warning: this version of 'sort' does not support the '-V' option …
        XILINX_VIVADO=…/new/AMD/2026.9/Vivado        ← wrong version

codex : (no warning, falls back to /usr/bin/sort)
        XILINX_VIVADO=…/new/AMD/2026.10/Vivado       ← correct
A version directory that is not a number 
$ mkdir -p $H/nonnum/Xilinx/Vivado/mybuild/bin
$ XILINX_HOME=$H/nonnum

claude: XILINX_VIVADO=/home/verilog/AMD/2026.1/Vivado     ← XILINX_HOME ignored
codex : XILINX_VIVADO=…/nonnum/Xilinx/Vivado/mybuild

The second is the more serious of the two: an explicit XILINX_HOME pointing at a real Vivado tree is discarded in silence because the directory happens not to start with a digit.

Recommended merge

Take xilinx_codex as the base, then apply six edits from xilinx_claude:

  1. Hoist the vendor list into a single xilinx_vendor_dirs variable used by both loops and the error message.
  2. Add the header comment describing all three layouts in one place.
  3. Collapse the multiple-installation warning to one line, naming the chosen directory.
  4. Lowercase the message text to match the rest of the file.
  5. Quote each path in the final error instead of expanding the array bare.
  6. Delete the two return 1 statements that follow error.
