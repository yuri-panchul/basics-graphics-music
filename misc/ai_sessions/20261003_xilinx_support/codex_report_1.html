Codex version — advantages

  • More robust when Windows sort.exe comes first in PATH.
  • Supports symlinked installations.
  • Avoids sorting entirely when an unversioned installation is found.
  • Uses an argument array rather than splitting a command string.

Codex version — disadvantages

  • Can mistakenly select a directory named backup as the newest version. This was reproduced in testing.
  • Repeats the vendor list.
  • Does not warn when multiple unversioned installations exist.

Claude version — advantages

  • Excludes obvious non-version directories such as backup.
  • Separates candidate collection from selection.
  • Keeps vendor names in one place and reports alternative installations.

Claude version — disadvantages

  • Can fall back to alphabetical ordering even when /usr/bin/sort supports version sorting.
  • Does not normalize Windows CRLF output.
  • Misses symlinked version directories.
  • Uses xargs echo for diagnostics, which can mishandle paths containing quotes or backslashes.

Verification

Tests covered mixed versions, nonnumeric directories, multiple unversioned installations, symlinked version directories, and simulated Windows sorting. Both selected 2026.10 over 2026.2 with Unix sort. Codex selected a backup directory when present; Claude excluded it. Codex recognized the symlinked version directory; Claude did not. Windows behavior was simulated, not tested on native Windows.

Recommendation

Retain the Codex sorting behavior and add Claude’s numeric-directory filter and centralized vendor list.
