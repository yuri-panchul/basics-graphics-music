What the baseline does

The script runs in the lab’s run/ directory. With nullglob on, it compiles every lab ../*.sv, then every labs/common/*.sv, then every peripherals/*.sv, then every lab ../*.v:

iverilog "$icarus_language_option" -s tb \
    -I .. -I ../cpu -I "$lab_dir/common" -I "$package_dir/peripherals" \
    ../*.sv "$lab_dir/common"/*.sv "$package_dir/peripherals"/*.sv \
    ../*.v

The shell expands the lab globs in alphabetical order. That order is why a package file can be compiled after a module that imports it. sv_file_list.f exists so a lab can name sources in compile order. Paths in the two lists that are in the tree are relative to the lab directory. The linked-list list names the package, the controller, the request generator, lab_top.sv, and tb.sv. The APS list names headers and sources under pkg/, aps_cpu/, and other subdirectories. It does not name lab_top.sv or tb.sv. Neither list names labs/common or peripherals.

On this machine, Icarus Verilog 12.0’s -f reads a command file relative to the compiler’s working directory. Blank lines, # comments, and // comments are ignored. A name ending in CR+LF still opened the file. A missing name is a preprocessor error. Those checks are about -f, which only Codex uses.

Claude

Claude keeps the baseline command and replaces only the two lab globs. If ../sv_file_list.f exists, a while read loop strips a trailing CR, skips an empty line, and appends ../ plus the rest of the line. Every accepted line goes into lab_sv_files, including a .v or .svh name. labs/common and peripherals are still globbed afterward. If the list is absent, ../*.sv is passed before those libraries and ../*.v after them, which is the baseline order. Empty arrays are expanded as ${array[@]+"${array[@]}"} so set -u does not fail on Bash 3.2 or on Bash older than 4.4.

Pros

  • The comment states the real constraint: a package must be compiled before the files that import it, the list has to contain tb.sv, and the paths match the Vivado flow (../ plus a lab-relative name).
  • The CR strip is both implemented and explained, so a list saved with Windows line endings still yields a usable path.
  • The empty-array comment names the actual range, Bash older than 4.4, and gives macOS Bash 3.2 as the example. That is the accurate form of this portability note.
  • Shared libraries stay on the command line. A lab list that only names lab files still compiles labs/common and peripherals, as the baseline did.
  • Include paths and the compiler’s working directory stay at the baseline. Quoted includes and vvp a.out keep their old meaning.
  • The loop is short. A reader can see that each line becomes one filename argument.
  • Labs with no sv_file_list.f keep the baseline glob order, including ../*.v after the libraries.

Cons

  • A # or // comment is not empty, so it is passed to iverilog as a filename. Icarus then reports a missing file. The lists in the tree have no comments today. A note added to a list breaks the compile.
  • Leading or trailing spaces are kept. tb.sv becomes the path ../ tb.sv.
  • The array is named lab_sv_files even when the line is a .v or .svh file. The name describes the no-list path, not the list path.
  • The script still lists labs/common/*.sv and peripherals/*.sv itself. That preserves baseline behavior. It is not a full stop to “listing the files by itself.”
  • Lines are always filenames. A list entry that was meant as an iverilog option, such as -I somewhere, becomes one broken path. The current lists do not contain options.
  • For the APS list, lab_top.sv and tb.sv are omitted because the list omits them and the lab glob is no longer used. -s tb then fails. The comment warns about tb.sv, and the APS list does not follow that warning.

Codex

Codex treats sv_file_list.f as an Icarus command file. When the file exists, a subshell cds to the lab directory and runs:

iverilog "$icarus_language_option" -s tb -o run/a.out \
    -I run -I . -I cpu \
    -I "$lab_dir/common" -I "$package_dir/peripherals" \
    -f sv_file_list.f

-o run/a.out puts the simulator back where vvp a.out expects it. The subshell ends before vvp, so GTKWave still starts in run/. The else branch is the baseline command, copied rather than rebuilt. nullglob is enabled only on that branch.

Pros

  • This is the smallest change that hands the list to Icarus instead of reimplementing a parser. Blank lines, # comments, // comments, and CR+LF names are handled by Icarus 12.0’s -f, as checked for this report.
  • The comment explains a real compiler rule: -f paths are relative to the working directory, not to the list file. The cd .. is the direct consequence, and -o run/a.out keeps the rest of the function working.
  • -I . and -I cpu are the lab-directory equivalents of the baseline’s -I .. and -I ../cpu. The rewrite matches the new working directory.
  • The subshell confines cd. A failed cd or iverilog still fails the pipeline under pipefail.
  • There is no Bash array, no set -u empty-array hazard, and no hand-written trim.
  • The no-list path is the original command, not a reconstruction. It cannot drift from the baseline by accident.
  • nullglob is not turned on for the list path, so a later failure cannot leave it set.

Cons

  • The list replaces every source argument, not only the lab globs. labs/common/*.sv and peripherals/*.sv are not compiled. Both lists in the tree omit those directories. A lab that instantiates a module from either directory fails until someone copies those files into the list. Header search still works, because -I for those directories remains.
  • The compiler’s working directory moves from run/ to the lab. A quoted include that is found relative to the current directory can now resolve to a different file. The baseline looked up such names from run/.
  • -I run is new. The baseline did not search the simulation directory. A generated file in run/ whose name matches an include can hide the intended header.
  • -f is a command file, not a filename list. A future line that starts with an option is an iverilog option. Claude and Grok would pass that same line as one filename. The current lists are filenames only, so this does not fire today.
  • The comment does not say that tb.sv has to be in the list. For APS, it is not, and -s tb fails. The same gap exists in the other two edits. Codex’s comment does not warn about it.
  • Behavior of comments and CR depends on the installed Icarus. The check for this report was version 12.0. The script does not probe -f.

Grok 4.7

Grok uses the same shape as Claude. The list replaces ../*.sv and ../*.v. Each kept line is prefixed with ../. labs/common and peripherals still follow. The no-list path still puts ../*.v after the libraries. The extra parsing, relative to Claude, is whitespace trimming and skipping lines that are empty or that start with # or // after trimming. The array is named lab_sources. The empty-array expansion is the same ${name[@]+"${name[@]}"} form.

Pros

  • Comments and blank lines are ignored in the shell, so a list with notes does not become a missing-file error. Claude would pass those lines through. Codex gets the same result only because Icarus -f ignores them.
  • Leading and trailing whitespace is removed, and a CR is removed before that. tb.sv and a Windows line both become ../tb.sv.
  • lab_sources does not claim that every entry is SystemVerilog. A .v or .svh line is still compiled, in list order.
  • Shared labs/common and peripherals sources stay on the command line, so the edit does not drop modules the baseline always compiled.
  • Include paths and the working directory stay at the baseline. vvp a.out does not need a new -o path.
  • local -a makes the two arrays explicit. The no-list branch preserves baseline order: lab .sv, common, peripherals, lab .v.
  • The empty-array expansion is safe under set -u on the Bash versions where "${array[@]}" is an error for an empty array.

Cons

  • The comment is thinner than Claude’s. It does not say why order matters, it does not say the list must include tb.sv, and it does not point at the Vivado convention of ../ plus a lab-relative path. A later editor can break the contract without a comment to catch it.
  • The portability comment says the empty-array form is for Bash 3.2 on macOS. The failure also happens on Bash 4.0 through 4.3. Claude’s wording, “older than 4.4, such as Bash 3.2,” is the better one.
  • The trim uses two nested parameter expansions. They do trim both ends, including an all-whitespace line, but they are harder to audit than Claude’s [ -n "$line" ] test.
  • A filename that actually starts with # or // is dropped. That is unlikely in this repository. It is still a silent filter.
  • The script still globs labs/common and peripherals. Like Claude, it does not stop listing every source itself.
  • The same APS hole remains. That list has no lab_top.sv and no tb.sv, and the lab glob is skipped, so -s tb fails. Grok’s comment does not mention this.
  • The design is the same manual parser as Claude’s, with a stricter line filter. It does not use iverilog -f, so comment handling is now two implementations: this shell filter, and Icarus’s own command-file syntax if someone later switches to -f.

How the approaches differ

Codex answered the request by giving the list to iverilog -f and deleting the source globs from that branch. The result is short, and the shell does not grow a parser. The cost is that the baseline’s shared-library sources disappear, the compiler runs in another directory, and one new include directory appears. That is a different compile from the one the script has been doing, even for a list that is only a lab-local ordering file.

Claude and Grok answered by replacing the lab globs and leaving the shared libraries in place. For the linked-list list, which already names tb.sv and the package first, both produce the same source order plus the old common and peripheral files. Claude writes the contract in the comment and keeps the parser minimal, at the cost of treating comments and padded lines as filenames. Grok filters those lines and names the array for mixed sources, at the cost of a denser trim and a comment that leaves out the tb.sv requirement and the Bash 4.0–4.3 case.

None of the three adds top-level lab files that the list forgot. The APS list is the existing example. A compatible reading of “use the list instead of listing the lab files,” which is what Claude and Grok implemented, still needs tb.sv in that list before Icarus can simulate APS. Codex needs that too, and it also needs every common or peripheral module the lab instantiates.
