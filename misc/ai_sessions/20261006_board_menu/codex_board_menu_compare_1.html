The strongest combined version would keep these advantages and fix the input edge cases below.

Both commits start from 77959f67, after the board-directory renames. Both working trees were clean when read and contained the same 113 top-level board directories. The comparison concerns scripts/steps/00_setup.source_bash, each implementation’s menu tests, and its README changes.

Both retain the existing nexys_a7 and zzz_postponed_and_retired entries. Therefore, “56 groups” is a menu count, not a claim that all 56 are current board products. Neither implementation reads pin assignments or constraints to build the menu.

How a board is chosen, in plain English

The shared setup first checks whether the calling script needs an FPGA board. A board named by a hackathon file takes precedence. Otherwise, an existing valid selection is reused unless the caller explicitly asks to choose again. The two-level menu runs when a new choice is needed.

Codex

  1. Read and sort the names of the directories directly inside boards.
  2. For each name, recognize the complete chain of known configuration endings. Remove that chain to obtain the board name. For example, tang_nano_9k_50mhz_hdmi_no_tm1638 becomes tang_nano_9k.
  3. Keep each board name once, in the order it first appears. Show those names and an exit item.
  4. After the user chooses a board number, collect the original directory names belonging to that board.
  5. If there is one configuration, select it immediately. If there are several, show their full names plus back and exit.
  6. Use the original directory name as the final selection. The existing setup writes fpga_board_selection with that name uncommented, then chooses the associated toolchain.

Claude

  1. Read and sort the same directory names.
  2. For each name, try removing every known matching ending, then repeat on what remains. Keep the shortest nonempty result, so overlapping endings do not leave a stray _no.
  3. Sort the distinct board names. Count each board’s configurations. Show the board and its count when there are several; show the full directory name when there is only one.
  4. Interpret the chosen number as an index into the board list. Collect that board’s original configuration names.
  5. Select a sole configuration immediately. Otherwise, show only each distinguishing suffix, plus back and exit. A configuration with no suffix is shown under the board name.
  6. Map the chosen number back to the full directory name. The same existing selection-file and toolchain logic handles the result.

Both keep de0, de0_nano and de0_nano_soc separate, as well as de1/de1_soc, de2/de2_115 and omdazz/omdazz_epm570. Ordinary invalid input is rejected; back returns to the board menu without saving an intermediate choice.

Verified findings

Fix first · Claude Leading zeros can select the wrong board or toolchain

Bash’s select accepts 010 as menu item 10. Claude then recalculates the array position with $(( REPLY - 1 )), where the leading zero makes the arithmetic octal. It consequently uses item 8. Codex uses the value supplied by select, avoiding that conversion.

The wrong 010 choices were reproduced through the complete setup script and written to temporary selection files. With a saved basys3 selection, first-level 08 also let the test wrapper resume with the old board and fpga_toolchain=none, after printing an arithmetic error. Without a saved choice, that wrapper ended with an unbound-variable error. The failure is therefore more than a cosmetic message.

Recommendation: after validating a nonempty selection, normalize REPLY explicitly as decimal, then use that one normalized number for all array indexing and control comparisons. Change the string comparison used for back to a numeric comparison. Add tests for 08, 09, 010 and zero-padded Back/Exit at both levels. Source: board indexing; Back comparison and variant indexing.

Synthetic names · Codex Menu commands collide with board names

With a test list de0 exit, choosing the board named exit cancels in Codex. With back de0, selecting back loops to the board menu instead of selecting it. Claude selects both names correctly because it identifies commands by their positions. No current repository directory has either reserved name.

Recommendation: adopt position-based dispatch from Claude, together with the decimal normalization described above. Display command entries distinctly, such as [Back] and [Exit], while preserving the actual directory names. Source: board controls; configuration controls.

Design choice Generic PMOD suffix versus a specific compound

Claude includes _pmod, so it can remove _pmod plus _hub75e_led_matrix. Codex lists _pmod_hub75e_led_matrix explicitly. Both correctly group the current Tang Primer 25K matrix configurations.

For the synthetic name new_board_pmod, Claude returns new_board; Codex keeps new_board_pmod. Claude’s rule is more general, while Codex’s rule is more conservative about unfamiliar names. Adopt the generic component only if the project intends a trailing _pmod always to identify a configuration, rather than a distinct model.

Inherited portability issue Redundant xargs options in the Darwin branch

Claude retains xargs -I % -L 1 basename '%'. Codex removes the redundant -L 1. When the Darwin branch was exercised on this Linux host using GNU tools, Claude produced a group named % with 113 configurations; Codex selected the intended board. The conflicting options prevent the intended replacement in this environment.

This is a branch-emulation result, not a native macOS test. The original flat-menu code already had the redundant options; it was not introduced by Claude’s menu change. Adopting Codex’s simplification reduces that tool-dependent behavior. Codex discovery; Claude discovery.

Advantages and disadvantages

Codex advantages

  • Compact implementation: the setup-script patch adds 151 lines and removes 19, versus Claude’s 293 added and 19 removed. Comments and whitespace are included in these counts.
  • One regex handles overlapping suffix chains without recursive shell calls. ECP5 names match the catalog’s model names.
  • Full configuration labels make the selected directory unambiguous. Local prompt variables and a cancellation return status keep the helper’s effects easier to reason about.
  • The supplied tests exercise discovery, persistence, toolchain dispatch, saved selections, hackathon overrides and platform branches through the actual setup script. Optional baseline comparison checks the original flat menu.

Codex disadvantages

  • Long repeated board prefixes make the variant menu harder to scan. The first menu has neither configuration counts nor a preview of a singleton’s suffix.
  • Text-based control dispatch reserves back and exit. An empty board list gets no useful diagnostic.
  • The regex requires understanding Bash matching and parameter expansion. Its suffix array is not alphabetized, making updates harder to audit.
  • A command substitution and pattern construction occur for each configuration. The tests require catalog updates for newly added models, even though runtime discovery does not use the catalog.

Claude advantages

  • Short variant labels and group counts help users navigate. Singletons expose the exact configuration name immediately.
  • The suffix list is alphabetized. Recursive exploration explicitly expresses the “try every suffix split” rule and avoids a subprocess for each base calculation.
  • Position-based control dispatch supports reserved board names. The empty-directory error gives a clear reason for failure.
  • The tests walk the menu using actual user choices, checking that every directory is reachable exactly once. Synthetic reserved-name and board-family cases complement that coverage.

Claude disadvantages

  • Leading-zero arithmetic is a confirmed selection bug. ECP5 handling is incomplete at the board-name level.
  • More parallel label/index bookkeeping creates additional ways for display and selected values to diverge. The helper exits the caller on cancellation and changes global prompt variables.
  • Recursion revisits overlapping suffix paths without caching. Group counting scans all records once for each distinct base, and sort -u adds an external operation. This is a scaling consideration, not a measured performance failure.
  • The shipped tests extract only the menu section and do not check full setup persistence or toolchain selection. They do not check subprocess exit codes, so some failures may be interpreted as “no selection.”

Neither test count nor patch size alone establishes quality. No startup-speed benchmark was performed. Both retain the repository’s existing whitespace-separated directory-name assumption, and both need the suffix policy updated when genuinely new configuration forms appear.

What each side should adopt

Codex can adopt from Claude

  1. Separate display labels from stored configuration names. Show short suffixes at level two, counts for multi-configuration groups and the full name for a singleton.
  2. Identify control entries by position. Preserve support for arbitrary board names, but normalize menu numbers as decimal before indexing.
  3. Add an explicit empty-directory error and reserved-name regression cases.
  4. Add a traversal test proving uniqueness. Complement the catalog-driven integration tests with a walk of the displayed menu that reaches every directory exactly once.
  5. Alphabetize the suffix list. Consider avoiding per-board command substitutions only after measuring whether they matter for interactive use.
  6. Consider sorting the final board names explicitly. Claude’s order places de0_nano before de0_nano_soc, independently of which configuration suffix happens to sort first. Update menu-order tests if adopting this behavior.

Claude can adopt from Codex

  1. Preserve the value selected by Bash, or normalize numeric indices correctly. Fix leading zeros before other refinements.
  2. Add _ecp5_yosys and an independent expected-model check, so complete reachability cannot hide incorrect grouping.
  3. Run the complete setup in temporary repositories. Check the exact saved file and toolchain, including existing selections and cancellation paths. Assert process status and use timeouts.
  4. Use local prompt state and return cancellation to the caller. End-of-input at the second menu can cancel directly without printing the first menu again.
  5. Adopt the xargs simplification. Consider the compact suffix-sequence regex if reducing recursive control flow improves maintainability for the project’s Bash audience.
Recommended convergence: keep the full original directory names as the sole saved identifiers; combine Claude’s display labels and configuration counts with Codex’s suffix coverage, scoped helper state and full-setup tests. Add decimal-safe index dispatch, explicit empty-list handling and the union of both suites’ edge cases. This is a recommendation; the compared implementations remain the recorded commits.

Evidence and verification limits

  • Codex suite: 10 tests passed, including all 113 ordinary selections against the original flat-menu script at 77959f67.
  • Claude suite: 17 tests passed, including exhaustive menu traversal and reserved-name cases.
  • Independent full-setup check for Claude: all 113 ordinary selections matched the baseline’s exact selection file and printed board/toolchain result. This closes a gap in Claude’s shipped tests for this review.
  • Additional probes: both base-name maps, first and second menu leading zeros, EOF, empty board lists, reserved names, generic PMOD and ECP5 forms, and the GNU-tools Darwin branch. The first-menu 010 and second-menu 49 → 010 defects were also checked with and without an existing saved selection.
  • Syntax: both complete Bash files passed bash -n. EDA setup functions were stubbed in temporary repositories; no synthesis, programming, license checks or physical hardware tests were performed. Native Windows, Cygwin, MSYS and macOS behavior remains unverified.

The additional probes deliberately test conditions missing from the passing suites. In particular, 113/113 ordinary-selection equivalence does not imply equivalence for every accepted spelling of a menu number.

Additional audit runner used for this report

The runner snapshots both local implementations under /tmp/board-menu-compare-1, probes isolated menus, then uses Codex’s temporary-repository harness to compare every Claude selection with the original flat menu. Run with Python 3.9 or later and Bash. The full-setup leading-zero probes were additional runs of the same harness.

def run_bash(source, answers='', args=()):
    return subprocess.run(['bash', '-c', source, 'audit', *args], input=answers,
                          capture_output=True, text=True, env=ENV, timeout=15)

def get_bases(name, boards):
    command = ('fpga_board_base_name "$board"' if name == 'codex' else
               'fpga_board_base "$board"; printf "%s\\n" "$fpga_board_base_result"')
    result = run_bash('set -Eeuo pipefail\n' + MENUS[name] +
