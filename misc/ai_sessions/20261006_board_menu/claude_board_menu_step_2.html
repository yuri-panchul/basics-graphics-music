Point 16: what an oracle is

Jargon of mine, and a poor choice of word — nothing to do with the company. In testing, the oracle is whatever tells the test what the right answer is. A test has two halves: run the thing, then ask the oracle whether the result was correct.

The reason it matters here is that a bad oracle can agree with a bug. If my test computed the expected grouping with the same suffix list the script uses, then a wrong suffix list would produce a wrong grouping and a wrong expectation, and the test would pass. That is a self-fulfilling oracle.

The two implementations picked different oracles, and that is the most interesting difference between the test suites:

OracleUsed byWhat it can catch
the directory listing itself — every directory must be reachable exactly onceclaudea board becoming unreachable, or reachable twice; says nothing about whether the grouping is sensible
boards/README.csv — group by the longest catalogued board name that is a prefixcodexa wrong grouping, because the expectation comes from the board catalog rather than from the suffix list
the old flat menu itself — replay all selections through bothcodexany behaviour change at all, including the saved file and the chosen toolchain

I will use all three. The last one is the strongest and I already borrowed it for the comparison report: 113 boards, old menu versus new, zero mismatches. Folding it into the test file is part of the plan.

Three things I need from you

1. Should arty_a7_35 and arty_a7_100 also become one board?
They are the same Digilent board with a different part, exactly like nexys_a7_50 and nexys_a7_100. You named only nexys_a7, so by default I will group only that and leave arty_a7_35 and arty_a7_100 as separate first-level entries. Adding them to the alias table is two more lines if you want the families treated alike. The same question applies to nexys4 and nexys4_ddr, which I would leave separate.
2. xargs -I % -L 1 — what did you need it for?
You are right that there was a reason, and I will not touch it blind. What I can tell you is what it does here: with GNU findutils, -I and -L are rejected as mutually exclusive, -I is dropped with a warning, and the board list becomes 113 copies of %. On BSD xargs, which is what macOS ships, -I implies -L 1 and the extra option is harmless. So the question is only whether some Windows xargs needs it. I will add a one-command probe you can paste into Git Bash on Windows and into a macOS terminal: 
printf 'a/b\nc/d\n' | xargs -I % -L 1 basename '%'
printf 'a/b\nc/d\n' | xargs -I %      basename '%'
If both print b and d everywhere you care about, the option can go. If you would rather close the question for good, the whole pipeline can be replaced by a loop over "$board_dir"/*/ that needs neither xargs nor GNU find -printf, and the macOS-versus-Linux branch disappears. Tell me which you prefer; it is not in any of the four commits above.
3. Should the _hackathon suffix stay in the suffix list?
Once those directories never reach the menu, the suffix has no work left to do. I will keep it with a comment explaining why it is there but unused, unless you would rather have it deleted.
