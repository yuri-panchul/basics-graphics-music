What to take from the competitor’s report

Adopt

  • Explicit C collation and explicit sorting of derived board names.
  • A short multi-configuration marker, as you suggested, instead of verbose count labels.
  • A menu traversal test that discovers actual displayed choices and proves unique reachability, complementing the full-setup harness.
  • Independent expected grouping rules, with your ECP5, Nexys and Arty clarifications encoded explicitly.
  • A targeted mutation check: removing _no_hdmi in a temporary test copy should make the overlap test fail. No production source needs to be altered for that check.

Do not carry over

  • Generic _pmod, removal of _ecp5, abbreviated second-level labels, or verbose first-level configuration counts.
  • Raw arithmetic on REPLY: the report’s recommendation to index by number needs the decimal-handling correction identified in the Codex review.
  • Reserved-name handling solely for hypothetical boards named exit and back.
  • A global result variable or recursive algorithm merely to chase the reported speed difference. Keep the regex and scoped helper state for this four-commit sequence.

The competitor’s timing table measures repeated base-name extraction. It is useful evidence of subprocess overhead, but it is not a measured 2.9× speedup of the entire interactive setup. A performance refactor can be considered later if actual startup measurements justify it.

What “oracle” means here

A test oracle is the source of expected answers used to decide whether the program behaved correctly. It is unrelated to Oracle Corporation or Oracle Database.

For example, a test can state independently that colorlight75b_ecp5_tm1638_yosys must belong to colorlight75b_ecp5. It then asks the Bash code for its result and compares the two. If the expected answer is generated using the same suffix-removal algorithm as the implementation, both can repeat the same mistake and the test may pass incorrectly.

The previous tests used boards/README.csv as an independent list of model names. That is helpful, but not infallible: the CSV currently lists the four affected ECP5 models without _ecp5 and lists Nexys A7 and Arty A7 chip sizes separately. The menu now groups these families while retaining their distinct configurations. The revised tests need explicit expected-result mappings for your naming policy, rather than treating the CSV as the final authority or changing it just to make a test pass.
