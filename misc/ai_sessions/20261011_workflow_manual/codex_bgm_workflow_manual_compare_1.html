Style and likely points of student confusion

The branch decision must happen before the first commit

Codex creates student/hyperbola in chapter 9 and tracks that branch on the second computer. This is a better repeatable workflow, but its screenshots show main. The discrepancy is explained, yet it still makes a beginner compare two states. Add one screenshot of the task branch and one of the PR’s base/head selectors.

Claude follows main consistently until its chapter 12 tip. Creating hyperbola at that late point does not remove the existing commit from main, and an already opened main-based PR does not automatically become a branch-based PR. The statement that main “then remains an exact copy” needs the condition that the branch was created before committing. Move this tip to chapter 9; avoid a disruptive history rewrite as a beginner remedy.

Preserving work needs conditions, not a promise

Claude’s “your changes are not lost during synchronization” needs the surrounding conditions made explicit: save and commit first, resolve conflicts deliberately, and avoid discarding commits. Its bare git stash does not include new untracked exercise files. Codex explains stash -u, apply and merge abort, but gives so many alternatives that readers may paste a whole sequence after an earlier command has failed. Both should insert a clear checkpoint: stop on an error; resolve it before executing the next stage.

Russian terminology and the main reading path

Claude’s screenshot → explanation → next screenshot rhythm is effective. Its introduction retains awkward fragments such as “А также небольшие различия…” and inconsistent forms such as VSCode, bash, XPACK and mixed transliterations. Codex has cleaner connective prose, but phrases such as “override,” “helper,” “early return” and a 40-character commit hash are distracting in a student-facing section. Use ordinary Russian explanations first and keep exact identifiers in short reference notes. Use “VS Code” consistently while preserving actual UI labels.

Codex should add a compact “run this → expect this result → if it fails” block to each route. Claude already has a useful common-script table. Both need a final student checklist: correct branch, source saved, intended diff only, simulation/compile results recorded, timing reviewed, board behavior observed, commit pushed, PR base verified. “Able to merge” is a textual merge result, not a SystemVerilog correctness check; Codex explicitly explains this.

Mobile use and publication

Claude’s page exceeds a 390 px viewport because long inline paths and tables can expand the document. Add wrapping for inline code/links and scrolling containers around tables. Codex already does both. Claude’s image tags omit width/height, which can cause layout movement while images load; this is a markup concern, separate from the reproduced overflow.

Claude’s HTML comment suggests copying the article into both GitHub Wiki and WordPress. Prefer the supplied Markdown for Wiki; keep the article fragment for a WordPress Custom HTML block and preview it in the actual theme. Codex supplies the separate fragment and clearer publishing instructions, though neither version has been tested in a live WordPress theme.

Claude includes two School photos added to the source directory at 22:28 and 22:51 on 11 October, after Codex’s 22:03 build. Their absence in Codex is an opportunity to refresh the article, not evidence that it ignored material available at its build time.
