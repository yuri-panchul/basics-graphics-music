The strongest solution combines features from both

Codex has stronger selection mechanics: numeric comparison includes builds, discovery does not depend on GNU sort, the QSF parser handles more literal forms, failed candidates fall through consistently, and the chosen binary directory becomes first on PATH. Its main weakness is that the device helper mistakes “Quartus knows this part's family” for “this installation supports the part.” Handwritten release rules mask some of that weakness.

Claude has a better source of installed-device information and avoids repeated launches through caching. Its latest revision checks both listed parts and installed families. However, the cache can be stale or collide between paths, GNU sort remains a dependency, and appending the chosen directory to PATH can leave another Quartus first.

The revisions have already converged. Both now honor parent-directory priority, recognize eight vendor-directory names, reject incomplete auto-discovered installations, deduplicate aliases during discovery, add the AX301 board to Quartus dispatch, and remove the obsolete old/new-version flag. Claims that Claude still lacks those fixes apply to its earlier commit, not the revision reviewed here.

These are code and behavior findings, not a ranking of the LLMs in general. Both worktrees were clean when frozen. Full commits and file hashes are in the snapshot manifest.

Search behavior in plain English

A board's QSF file names its FPGA part. The scripts try to find an installed Quartus that can handle it. The board name “DE23-Lite” does not mean Quartus Lite: Codex explicitly requires Pro for its Agilex 3 part; Claude asks the tools which parts and families they provide.

Both use this normal order of locations. Stop at the first tier with a usable candidate; choose the preferred installation within that tier.

QUARTUS_ROOTDIR→first Quartus on PATH→INTEL_FPGA_HOME→ALTERA_HOME→QUARTUS_HOME→default parents together

On Linux, the defaults are the user's home directory, /opt and /tools. On Cygwin/MSYS, they are /c, /d and /e, corresponding to Windows drives C:\, D:\ and E:\. This searches known directory shapes, not the entire computer recursively.

A parent override names the directory above a vendor directory. Both recognize altera, altera_lite, altera_std, altera_pro, intelFPGA, intelFPGA_lite, intelFPGA_std and intelFPGA_pro. A typical result is /opt/altera_lite/25.1std/quartus. Both read edition information from the installation rather than assuming that “altera” means old or “std” means Standard.

Codex: validate every candidate, then select

  1. Read the board's part. Accept a literal DEVICE assignment, including optional double quotes and tabs. Use the last matching assignment. Error if no literal part can be read.
  2. Try QUARTUS_ROOTDIR, then the first Quartus on PATH. Apply the same executable, identity and compatibility checks as automatic discovery. Warn and continue if the candidate fails.
  3. Try each parent override separately. INTEL_FPGA_HOME, then ALTERA_HOME, then QUARTUS_HOME. The first parent with a compatible candidate wins over all later tiers.
  4. Otherwise pool all defaults. Look for <parent>/<vendor>/[0-9]*/quartus. The version directory must start with a digit. Resolve aliases and avoid probing the same canonical root twice in this setup.
  5. Check each installation. Require GUI, shell and programmer. Linux uses bin; Windows tries bin64, then bin. Read version.txt, falling back to the version banner. Apply handwritten family/release limits and the legacy EPM570 wrapper's 13.1 ceiling, then run the Tcl family-name query. Warn about problematic path characters.
  6. Rank survivors in the winning tier. Lite/Web wins over other editions even if older. Otherwise compare numeric version, including build. Standard/Subscription wins a tie against Pro. Remaining ties keep collection order.
  7. Activate the result. Set QUARTUS_ROOTDIR and the three absolute tool paths. Put the selected bin first on PATH, removing duplicate copies of it. Error if no candidate survives.

Claude: ask the tools, cache answers, allow overrides

  1. Read the board's part. A grep/awk pipeline takes the first matching DEVICE value. It expects spaces, retains quotes, and a missing/unreadable assignment leaves the part empty. An empty part disables compatibility filtering.
  2. Honor QUARTUS_ROOTDIR. Require the executables. If probing succeeds but says unsupported, warn and still use it. A failed probe does not prevent use. This is a force-override policy.
  3. Try the first Quartus on PATH. Use it if the device check succeeds, if no part was parsed, or if probing fails. Only a definite unsupported result causes a warning and continued search.
  4. Search parent tiers, then pooled defaults. The order matches Codex. Under each vendor, accept any child directory containing a complete installation, including current. Canonicalize and deduplicate within the collection.
  5. Ask each installation what it contains. Try bin64 before bin. Fetch the version banner, available families and listed parts. Cache them by transformed path and quartus_sh timestamp. An exact listed part passes; otherwise find its family and check that the family is installed.
  6. Rank survivors. Prefer Lite/Web, then newest release, then Standard over Pro on equal releases. Use GNU sort. Discard build numbers. Subscription becomes Unknown and ranks below recognized editions. Remaining ties use sort's whole-line comparison.
  7. Allow a final override if nothing is compatible. If a parent override was supplied, rank its installations without the part check and use the best with a warning. Otherwise error.
  8. Activate the result. Set the root and absolute tool variables, but append the selected bin to PATH. Earlier Quartus entries remain ahead of it.

The device check needs careful wording

A family name is not proof that the family is installed. In real read-only queries, local Quartus 25.1 Lite recognized the families of Cyclone II and III parts even though those families were not installed. Codex's helper accepts a nonempty family name; its separate release limits reject these particular old-family examples before that helper runs.

An unlisted part is not automatically unusable either. Quartus 13.1 Web does not enumerate EP3C120F780C6 but reports its Cyclone III family as installed. Claude's newer fallback accepts this case. Claude's local report describes a successful compile/fit, but this comparison did not repeat compilation and does not treat database queries as proof of a completed build.

Advantages and disadvantages

Codex advantages

  • Consistent validation and fallback. Overrides and PATH candidates face the same checks as automatic candidates; failed queries do not silently qualify a tool.
  • Predictable ranking. Builds participate, Subscription is recognized, no external sort is needed, and remaining ties have stable collection order.
  • Better input and path handling. The literal QSF parser accepts quotes/tabs and refuses a missing target. Arrays preserve paths; character warnings implement the requested behavior; PATH starts with the selected tools.
  • Review support. A small separate Tcl helper, updated scripts/README.md policy and 30 committed regression tests help future changes.
  • No cache dependency. Rechecking sees current device answers and requires no writable cache directory.

Codex disadvantages

  • Device validation is weaker than advertised. Family recognition does not establish installed support. Current mocks do not expose the real API distinction.
  • Handwritten compatibility knowledge can age. Family prefixes and version ceilings need maintenance and may reject a valid new combination before querying Quartus.
  • Repeated startups. Every setup re-probes eligible candidates. The two-candidate repeat test still launches Quartus twice.
  • No force override. Consistent validation helps automation but can frustrate a user deliberately choosing a release the policy rejects.
  • Narrower accepted inputs. Collection requires digit-prefixed directories; QSF parsing is not a general Tcl interpreter; unknown editions are rejected. Valid version.txt metadata is trusted without comparing the executable banner.

Claude advantages

  • More informative device queries. Listed parts plus installed families avoid depending only on known family names or only on enumerated parts.
  • Cached answers save startup. Repeating the two-candidate search launches zero Quartus processes. Identity, families and parts are gathered together.
  • Less handwritten device knowledge. Ordinary support comes from the installation, so later releases and new families can participate without new prefix/version rules.
  • User escape hatches. Explicit roots can proceed with a warning despite an unsupported result. Parent overrides also offer last-resort selection.
  • Flexible names and useful summaries. Non-numeric children can participate; no-match diagnostics can list editions and versions. Recent fixes preserve priority and skip incomplete installations.

Claude disadvantages

  • Cache correctness. Device-data changes can stay stale; path normalization can collide; a broken cache directory prevents discovery. Shared temporary Tcl filenames and direct cache writes also create concurrency risks visible in code, not reproduced here.
  • PATH inconsistency. Appending the chosen bin leaves another tool first. Absolute synthesis/programming variables mitigate this, but bare commands can still use a different Quartus.
  • Failures can remove protection. Missing/tabbed DEVICE assignments disable filtering. Failed PATH probes are accepted. An empty family answer is cached and may hide support added later.
  • Ranking loses information. Builds disappear, Subscription becomes Unknown, and GNU sort is required. Newline/tab record separators constrain unusual path names.
  • Missing requested safeguards. No installation-path character warning, no legacy-wrapper ceiling, no committed Quartus tests found, and no updated discovery policy in scripts/README.md. Discovery function names retain intel_fpga despite the requested naming direction.

The discovery source file is 886 lines in Codex and 1,036 in this Claude revision; totals include the shared Questa/synthesis/programming tail and do not measure correctness. Both retain stale Quartus instructions in scripts/steps/README.md; Codex's newer README does not remove that conflicting guidance.

+    if ! quartus_candidate_version=$(quartus_version_key "$quartus_version")

+        quartus_rejection="Cannot normalize version '$quartus_version'."

+# Read literal QSF data without executing arbitrary Tcl from the board file.

+quartus_read_target ()
+{
+    local quartus_line
+    local quartus_pattern='^[[:space:]]*set_global_assignment[[:space:]]+-name[[:space:]]+DEVICE[[:space:]]+"?([[:alnum:]]+)"?([[:space:]]|$)'
+    quartus_target_part=

+    while IFS= read -r quartus_line || [ -n "$quartus_line" ]

+        if [[ "$quartus_line" =~ $quartus_pattern ]]
+        then
+            quartus_target_part=${BASH_REMATCH[1]}
+        fi
+    done < "$board_dir/$fpga_board/board_specific.qsf"
+
+    if [ -z "$quartus_target_part" ]
+    then
+        error "cannot read a literal DEVICE assignment for board '$fpga_board'."

+    fi

+    [ "$1" = Lite ] || [ "$1" = Web ]

+# The device database provides the final exact-part check, including old updates.
+# Family limits: https://www.altera.com/design/guidance/software/device-support
+
+quartus_family_compatible ()
+{
+    local quartus_version="$1" quartus_edition="$2" quartus_limit=
+
+    case "$quartus_target_part" in
+        EP1C*)
+            if quartus_free_edition "$quartus_edition"
+            then
+                quartus_limit=11.0.1.999999
+            else
+                quartus_limit=13.0.1.999999
+            fi
+        ;;
+        EP2C*) quartus_limit=13.0.1.999999 ;;
+        EP3C*) quartus_limit=13.1.0.999999 ;;
+        A3*)
+            [ "$quartus_edition" = Pro ] || return 1
+            quartus_version_newer 25.1 "$quartus_version" && return 1
+        ;;
+        10M*)
+            quartus_version_newer 14.0 "$quartus_version" && return 1
+        ;;
+    esac
+
+    case "$quartus_target_part" in
+        EP1C* | EP2C* | EP3C* | EP4C* | 5C* | 10M* | EPM*)
+            [ "$quartus_edition" = Pro ] && return 1
+        ;;
+    esac
+
+    if [ "$fpga_board" = omdazz_epm570_quartus_13_1_or_older ]
+    then
+        quartus_limit=13.1.0.999999
+    fi
+
+    if [ -n "$quartus_limit" ] && quartus_version_newer "$quartus_version" "$quartus_limit"
+    then
+        return 1
+    fi
+
+    return 0
+}

+quartus_warn_install_path ()

+# Arrays are local to quartus_setup; helpers append without splitting path names.
+
+quartus_collect_parent ()
+{
+    local quartus_parent="$1" quartus_vendor quartus_root
+    [ -n "$quartus_parent" ] || return 0
+
+    if [ "$OSTYPE" = cygwin ] || [ "$OSTYPE" = msys ]
+    then
+        quartus_parent=$(cygpath -u "$quartus_parent") || return 1
+    fi
+
+    for quartus_vendor in altera altera_lite altera_std altera_pro \
+        intelFPGA intelFPGA_lite intelFPGA_pro intelFPGA_std
+    do
+        for quartus_root in "$quartus_parent/$quartus_vendor/"[0-9]*/quartus
+        do
+            [ -d "$quartus_root" ] || continue
+            quartus_candidates+=("$quartus_root")
+        done
+    done
+}

+# Prefer Lite/Web; otherwise compare versions before the Standard/Pro tie-break.
+
+quartus_candidate_better ()
+{
+    [ -n "$quartus_best_root" ] || return 0
+
+    if quartus_free_edition "$quartus_candidate_edition" && ! quartus_free_edition "$quartus_best_edition"
+    then
+        return 0
+    fi
+
+    if ! quartus_free_edition "$quartus_candidate_edition" && quartus_free_edition "$quartus_best_edition"
+    then
+        return 1
+    fi
+
+    quartus_version_newer "$quartus_candidate_version" "$quartus_best_version" && return 0
+    quartus_version_newer "$quartus_best_version" "$quartus_candidate_version" && return 1
+
+    if [ "$quartus_candidate_edition" != Pro ] && [ "$quartus_best_edition" = Pro ]
+    then
+        return 0
+    fi
+
+    # Stable collection order resolves all remaining ties.
+    return 1
+}

+quartus_consider_candidate ()
+{
+    local quartus_root="$1" quartus_bin quartus_seen quartus_output
+    local quartus_candidate_version= quartus_candidate_edition=
+    local quartus_rejection= quartus_query="$script_dir/fpga/quartus_has_device.tcl"
+    local -a quartus_bins=(bin)
+
+    if [ "$OSTYPE" = cygwin ] || [ "$OSTYPE" = msys ]
+    then
+        quartus_root=$(cygpath -u "$quartus_root") || return 1
+        quartus_query=$(cygpath -m "$quartus_query") || return 1
+        quartus_bins=(bin64 bin)
+    fi
+
+    if ! quartus_root=$(readlink -f "$quartus_root") || [ ! -d "$quartus_root" ]
+    then
+        warning "Quartus directory '$1' does not exist."
+
+        return 0
+    fi
+
+    for quartus_seen in "${quartus_seen_roots[@]}"
+    do
+        [ "$quartus_seen" = "$quartus_root" ] && return 0
+    done
+
+    quartus_seen_roots+=("$quartus_root")
+    quartus_warn_install_path "$quartus_root"
+
+    for quartus_bin in "${quartus_bins[@]}"
+    do
+        if [ ! -x "$quartus_root/$quartus_bin/quartus$exe" ] ||
+           [ ! -x "$quartus_root/$quartus_bin/quartus_sh$exe" ] ||
+           [ ! -x "$quartus_root/$quartus_bin/quartus_pgm$exe" ]
+        then
+            if [ -z "$quartus_rejection" ]
+            then
+                quartus_rejection="Missing executable GUI, shell, or programmer in ${quartus_bins[*]}."
+            fi
+
+            continue
+        fi
+
+        quartus_read_identity "$quartus_root" "$quartus_bin" || continue
+
+        if ! quartus_family_compatible "$quartus_candidate_version" "$quartus_candidate_edition"
+        then
+            quartus_rejection="$quartus_candidate_edition $quartus_candidate_version is incompatible with $quartus_target_part or the wrapper's version limit."
+            break
+        fi
+
+        # Scope QUARTUS_ROOTDIR to this process; an incoming override must not redirect it.
+        # The Tcl helper checks installed parts only, without checking licenses.
+
+        if ! quartus_output=$(QUARTUS_ROOTDIR="$quartus_root" \
+            "$quartus_root/$quartus_bin/quartus_sh$exe" -t "$quartus_query" "$quartus_target_part" 2>&1) ||
+           [[ "$quartus_output" != *"BGM_DEVICE_SUPPORTED=$quartus_target_part"* ]]
+        then
+            quartus_rejection="Device database query failed for $quartus_target_part; check installed device packages and tool dependencies."
+            continue
+        fi
+
+        if quartus_candidate_better
+        then
+            quartus_best_root="$quartus_root"
+            quartus_best_bin="$quartus_bin"
+            quartus_best_version="$quartus_candidate_version"
+            quartus_best_edition="$quartus_candidate_edition"
+        fi
+
         return 0
     done
 
+    warning "Skipping Quartus '$quartus_root'." "$quartus_rejection"
+}
+
+quartus_choose_candidates ()
+{
+    local quartus_candidate
+
+    for quartus_candidate in "${quartus_candidates[@]}"
+    do
+        quartus_consider_candidate "$quartus_candidate"
+    done
+
+    [ -n "$quartus_best_root" ]
+}
+
+quartus_activate ()
+{
+    local quartus_selected_bin="$quartus_best_root/$quartus_best_bin"
+    local quartus_entry quartus_remaining="${PATH-}" quartus_new_path="$quartus_selected_bin"
+
+    # Retain the original PATH order and empty entries, removing duplicate selected bins.
+
+    while [ -n "$quartus_remaining" ]
+    do
+        # %% removes the longest colon suffix, leaving the first PATH entry.
+        quartus_entry=${quartus_remaining%%:*}
+
+        if [ "$quartus_entry" != "$quartus_selected_bin" ]
+        then
+            quartus_new_path+=":$quartus_entry"
+        fi
+
+        [[ "$quartus_remaining" = *:* ]] || break
+
+        # # removes the first PATH entry and its colon separator.
+        quartus_remaining=${quartus_remaining#*:}
+
+        [ -n "$quartus_remaining" ] || quartus_new_path+=:
+    done
+
+    export QUARTUS_ROOTDIR="$quartus_best_root"
+    export PATH="$quartus_new_path"
+    quartus_bin_dir="$quartus_best_bin"
+    quartus_full_real_path="$quartus_selected_bin/quartus$exe"
+    quartus_sh_full_real_path="$quartus_selected_bin/quartus_sh$exe"
+    quartus_pgm_full_real_path="$quartus_selected_bin/quartus_pgm$exe"
+
+    # %/* strips the final path component, like dirname here; Questa still needs this name.
+    choosen_version_dir=${quartus_best_root%/*}
+
+    info "Selected Quartus $quartus_best_edition $quartus_best_version for"   \
+         "'$fpga_board' ($quartus_target_part), using $quartus_source."       \
+         "QUARTUS_ROOTDIR=$QUARTUS_ROOTDIR"
+}
+
+quartus_setup ()
+{
+    local quartus_target_part quartus_parent quartus_override quartus_path_command
+    local quartus_best_root= quartus_best_bin= quartus_best_version= quartus_best_edition=
+    local quartus_source
+    local -a quartus_candidates=() quartus_seen_roots=() quartus_default_parents=()
+
+    if [ "$OSTYPE" = linux-gnu ]
+    then
+        quartus_default_parents=("$HOME" /opt /tools)
+
+    elif [ "$OSTYPE" = cygwin ] || [ "$OSTYPE" = msys ]
+    then
+        # These paths correspond to Windows drives C:, D: and E:.
+        quartus_default_parents=(/c /d /e)
+    else
+        error "Quartus discovery does not support OS / platform '$OSTYPE'."
+
+        return 1
+    fi
+
+    # Preserve the existing RED OS workaround when called from a run directory.
+
+    if [ "${inside_run_dir-}" = 1 ] && [ ! -f /usr/lib64/libcrypt.so.1 ] &&
+       [ -f /usr/lib64/libcrypt.so ]
+    then
+        ln -sf /usr/lib64/libcrypt.so libcrypt.so.1
+
+        # :+ adds the existing library path and separator only when it is nonempty.
+        export LD_LIBRARY_PATH="${LD_LIBRARY_PATH:+$LD_LIBRARY_PATH:}$PWD"
+    fi
+
+    quartus_read_target || return 1
+
+    if [ -n "${QUARTUS_ROOTDIR-}" ]
+    then
+        quartus_candidates=("$QUARTUS_ROOTDIR")
+        quartus_source=QUARTUS_ROOTDIR
+
+        if quartus_choose_candidates
+        then
+            quartus_activate
+            return 0
+        fi
+    fi
+
+    if quartus_path_command=$(type -P "quartus$exe")
+    then
+        quartus_path_command=$(readlink -f "$quartus_path_command")
+
+        case "$quartus_path_command" in
+            */quartus/bin/quartus"$exe" | */quartus/bin64/quartus"$exe")
+                # %/* removes the executable filename, equivalent to dirname here.
+                quartus_path_command=${quartus_path_command%/*}
+
+                # %/* removes bin or bin64, leaving the Quartus root directory.
+                quartus_path_command=${quartus_path_command%/*}
+
+                quartus_candidates=("$quartus_path_command")
+                quartus_source=PATH
+
+                if quartus_choose_candidates
+                then
+                    quartus_activate
+                    return 0
+                fi
+            ;;
+            *)
+                warning "Quartus on PATH is outside a quartus/bin or quartus/bin64 installation."  \
+                        "Set QUARTUS_ROOTDIR to identify its installation; continuing discovery."
+            ;;
+        esac
+    fi
+
+    for quartus_override in INTEL_FPGA_HOME ALTERA_HOME QUARTUS_HOME
+    do
+        # ! performs indirect expansion; - tolerates an unset public override.
+        quartus_parent=${!quartus_override-}
+
+        [ -n "$quartus_parent" ] || continue
+        quartus_candidates=()
+        quartus_collect_parent "$quartus_parent"
+        quartus_source="$quartus_override='$quartus_parent'"
+
+        if quartus_choose_candidates
+        then
+            quartus_activate
+            return 0
+        fi
+
+        warning "No compatible Quartus installation under $quartus_source."  \
+                "Continuing with lower-priority locations."
+    done
+
+    quartus_candidates=()
+
+    for quartus_parent in "${quartus_default_parents[@]}"
+    do
+        quartus_collect_parent "$quartus_parent"
+    done
+
+    quartus_source="default installation parents: ${quartus_default_parents[*]}"
+
+    if quartus_choose_candidates
+    then
+        quartus_activate
+        return 0
+    fi
+
+    error "cannot find a compatible Quartus installation for '$fpga_board'"   \
+          "($quartus_target_part) under ${quartus_default_parents[*]}."       \
+          "Set QUARTUS_ROOTDIR to a specific quartus directory, or set"       \
+          "INTEL_FPGA_HOME, ALTERA_HOME or QUARTUS_HOME to the parent of"     \
+          "the altera*, intelFPGA* installation directories."
+
     return 1
 }
