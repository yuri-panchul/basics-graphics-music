Proposed selection rules

Compatibility is mandatory at every stage, including explicit overrides. An incompatible installation is never selected merely because it is first on PATH, newest, free, or under a preferred parent.

Interpretation of requirements 5 and 8: explicit environment and PATH choices retain priority over automatic discovery. Within each eligible search tier, prefer Lite/Web and then newer versions. Automatic default directories form one candidate pool, so a compatible newer installation under /opt can beat an older one under $HOME. This deliberately fixes the current first-directory behavior while retaining explicit override priorities.
  1. Determine the target. Read the board’s configured DEVICE, determine the family, and apply any documented wrapper-specific restriction. Missing or ambiguous board metadata must produce an actionable error.
  2. Try QUARTUS_ROOTDIR. Validate its tools, version, edition, and exact target support. A usable compatible choice wins. Warn clearly about a missing, unidentifiable, or incompatible override before continuing.
  3. Try the existing Quartus on PATH. Resolve its installation and perform the same checks. Preserve the preference for an already configured compatible environment; do not assume successful command lookup proves compatibility.
  4. Try named parent locations in order: INTEL_FPGA_HOME, ALTERA_HOME, then QUARTUS_HOME. These keep their current parent-of-installation-directories meaning. Scan all recognized vendor/edition folders and versions under each parent. Apply this to old and new boards; do not ignore INTEL_FPGA_HOME for legacy devices.
  5. Collect automatic defaults. Linux: $HOME, /opt, /tools. Cygwin/MSYS: /c, /d, /e (Windows drives C:, D:, E:). Deduplicate installations reached through repeated parents or symlinks.
  6. Filter and rank within the winning tier. If there are eligible Lite/Web candidates, choose the newest of them. Otherwise choose the newest eligible Standard/Subscription or Pro candidate; prefer Standard/Subscription only for equal versions. Remaining ties use stable collection order: parent, documented vendor order, then version-directory glob order. Canonical paths are used to deduplicate aliases.
  7. Publish one coherent toolchain. Set QUARTUS_ROOTDIR and the absolute paths to its GUI, shell, and programmer. Put that selected executable directory first on PATH, without duplicate insertion, so later commands agree with the choice. Inspect incoming PATH before changing it.
  8. Explain the outcome. Report selected edition, version, part, path, and selection source. On failure, list rejected candidates with reasons such as incompatible family, missing device package, missing tools, or an unreadable version. Warn about unsupported installation-path characters. Do not check or use license availability when selecting an installation.
