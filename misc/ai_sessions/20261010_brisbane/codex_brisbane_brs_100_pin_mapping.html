Keep the board pinout in constraints.
Put peripheral wiring in the wrapper.

The new _by_codex configurations keep BrisbaneSilicon’s GPIO names and all package-pin assignments. LCD, TM1638, microphone and DAC connections are made in board_specific_top.sv. The earlier implementations are preserved as _by_codex_alt.

This follows BGM’s board-support convention: the manufacturer’s CST describes the physical board, while the HDL wrapper describes what the lab connects to it. The same principle applies to XDC and QSF files, although those formats can also contain project settings or timing constraints.

How a signal reaches the header

1. Peripheral signal
The LCD controller produces LCD_R[0], the least significant red bit.
2. HDL connection
assign pad_io[5:1] = LCD_R;
Red bit 0 reaches GPIO 1.
3. Manufacturer pinout
IO_LOC "pad_io[1]" 25;
FPGA pin 25 reaches board header J5.1.

In the alternative, the CST directly says IO_LOC "LCD_R[0]" 25;. Both routes reach the same pin and use the same jumper to LCD adapter J2.30. The new assignment is a connection, not a clocked operation; it adds no pipeline cycle.

  1. Select the panel resolution in the BGM board menu. All four configurations group under brisbane_brs_100.
  2. The selected wrapper exposes the manufacturer’s clock, buttons, LEDs, UART, flash and inout [32:1] pad_io ports.
  3. LCD RGB occupies GPIOs 1–16, followed by LCD clock and controls on 17–20. TM1638 uses 21–23, microphone 24–26, DAC 27–29, and the lab’s spare GPIOs use 30–32.
  4. The CST binds these board signals to package pins. Its electrical attributes still govern voltage standards, pulls and drive strength.
  5. The SDC constrains the renamed physical ports. LCD data/control delays apply to GPIOs 1–16 and 18–20; GPIO 17 is the forwarded clock.

What actually changed beyond the names

The physical jumper map, LCD timing profiles, lab interfaces and shared peripheral drivers are unchanged. This is not a claim that the two constraint files are electrically identical:

  • Manufacturer defaults retained: header outputs now retain DRIVE=8 and pulldowns from the vendor file. Most alternative header ports used no pull and left drive strength unspecified. The new spare GPIOs therefore also have weak pulldowns in hardware.
  • 1.8 V bank made explicit: eight existing button/LED lines gain IO_TYPE=LVCMOS18. The vendor file omitted the explicit standard on those pins; its physical bank voltage still matters.
  • TM1638 DIO exception: GPIO 21 changes from pulldown to pullup for the bidirectional data line through the level translator. A vendor default is not a substitute for checking the attached circuit.
  • Input exceptions: flash MISO and microphone SD (GPIO 26) lose the vendor’s DRIVE=8 attribute. Gowin rejected that output-drive setting on these synthesized inputs. GPIO 26 retains its pulldown for an absent microphone. Spare GPIOs 30–32 also omit DRIVE so that a lab may use them as inputs; an input-only lab probe reproduced the same Gowin error on all three pins. Output use remains supported with the tool’s default drive setting.
  • Unused flash pins made explicit: the new top retains all four manufacturer flash names. CS stays high, CLK and MOSI stay low, MISO is input-only. The alternative constrained only CS. No flash programming is introduced.

Thus, the new CST has the original 47 locations, fourteen edited electrical-setting lines, provenance comments and a final newline. A byte-for-byte upstream copy is saved beside it as manufacturer_location.cst.txt; the automated test checks its SHA-256 and the permitted differences.

Bidirectional signals need real bidirectional connections

Declaring the header inout does not make every peripheral bidirectional. Output assignments drive LCD and audio outputs; the microphone data pin is only read. TM1638 connects directly through .sio_data(pad_io[21]), and the lab uses .gpio(pad_io[32:30]). Their drivers release the net with high impedance when reading.

A one-way assign alias would not preserve both directions. The tests exercise TM1638 drive/read/release and drive the spare GPIOs from each side. They also walk a one bit through the header outputs and verify microphone input independently. Simulation checks connections and digital contention; it does not model the physical level translator or prove electrical compatibility.

Validation and limitations

All five BRS-100 test groups pass, including 12 RGB-latency/frame cases, 30 wrapper cases, pin/provenance checks and mocked programmer dispatch. After the final input-only constraint adjustment, the pin-map and provenance groups were rerun successfully. All 22 menu tests pass: 116 configurations in 53 board groups.

The final manufacturer-GPIO wrappers completed synthesis, placement, routing and bitstream generation for these temporary C6/I5 checks. The table reports the constrained timing paths only.

Gowin’s SDC parser in this flow does not accept Tcl set variables; the final constraints use explicit port lists. Physical constraints and timing constraints must both survive a real tool run, even when RTL simulation passes.

The installed Gowin Education 1.9.11.03 database does not accept the manufacturer’s GW1NR-LV9QN88PC7/I6. Temporary builds use the C6/I5 model for limited synthesis, pin and timing checks only. The board target remains C7/I6, with no automatic fallback. No hardware was programmed, and no physical LCD, TM1638, microphone or DAC result is claimed.

UART, TM1638 and I²S external timing is not fully constrained. LCD output delays depend on the panel setup/hold assumptions and jumper skew documented in the READMEs. The exact chip, actual panel, power arrangement and assembled wiring still need verification.

Recommendation for BGM

Use the manufacturer-style versions as the normal basis for future BRS-100 configurations. Keep the preserved alternatives for comparison. Put the board pinout and board electrical facts in the constraint file; put expansion-module functions in a clearly commented section of the wrapper. Retain the original vendor file and record every necessary departure.

When moving a peripheral, review three things together: the HDL connection, its timing constraints, and the pin’s electrical settings. Keep the wiring table and diagrams in sync, and verify input/output direction in simulation and in the synthesized I/O report. “Manufacturer file preserved” should mean a small, explainable diff, not an unexamined copy.
